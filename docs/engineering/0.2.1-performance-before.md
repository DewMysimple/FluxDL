# 0.2.1 优化前基线

2026-11-09，Windows11 x64。实施前main/ffa76eb与实际origin同SHA、工作树干净；旧生产Manager fixture实际每组20次，随后旧debug真实原创HTTP媒体20次。旧debug报告没有编译revision，无法仅由报告证明二进制对应精确源码，因此不把它作为主要因果对照。原用户一次7.82秒/32.95秒只作问题线索，不参与任何分位数。

旧版fixture在修改Rust前实际重新编译运行。元数据固定60ms、首次进度前100ms，真实spawn/SQLite/调度；默认文件writer开启。下表与去标识的前20次原始阶段数字相符，异常场景与合成查询数据未混入。

同一阶段存在包含关系，不能相加。首次解析包含真实引擎进程开销；fixture是受控协议程序，不代表网站速度。旧版独立入队墙钟p50 writer关75.799ms/开77.418ms，均20次，不等同于前端IPC时钟。

主要对照采用同一0.2.1 debug二进制的A完整复核/B可信预览策略，保留相同验证规则、媒体/引擎/参数，并按B,A,A,B轮换，各20次。这能隔离入队重复提取的影响，避免将旧debug来源不明、OS缓存和引擎版本差异当成性能收益。详见[后测](0.2.1-performance-after.md)和[逐样本数据](0.2.1-latency-samples.json)。
