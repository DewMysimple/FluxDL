## 指标定义

- 启动加载：实际 `Persistence::open`，包含 quick_check、JSON 反序列化、历史文件存在性检查、排序及现有启动全量保存。
- 新增：准备 N 条历史及一条新任务，测量实际 `Persistence::save`。每次采样前恢复历史集合，复位耗时不计入该样本。
- 单条更新：仅改变活动任务的下载字节和进度，测量生产 `save` 的全部工作；旧实现仍删除并重写所有任务。
- 批进度：每个样本连续执行 20 次有数据变化的持久化保存。它模拟 20 次保存时机，不是 20 个原始 yt-dlp 事件，也没有等待真实的两秒节流间隔。
- 终态：采样前恢复 Downloading，测量状态改为 Completed 后的实际保存；复位耗时不计入。
- 快照：生产 `AppSnapshot` 的 `serde_json::to_vec` 耗时与 UTF-8 字节数，不包含 Manager 锁内克隆、锁外文件检查、IPC 传输或 WebView 渲染。

## 保护测试结果与测量边界

本次持久化过滤测试实际通过 5 项：原有损坏文件备份与活动任务中断，以及新增的手工 v1 表结构读取、重复保存后的最新字段与无重复记录、全部九种状态的重启语义。新增测试只补在 `persistence.rs` 的 test 模块，生产 Manager、模型和持久化逻辑未改。

本阶段没有通过这些测试宣称未知 JSON 字段、未来 schema、未知状态、增量写入版本保护或终态失败重试已经兼容；这些是阶段 3 的实现和测试范围。

运行使用已写入数据的 OS 缓存，属于本机开发环境的顺序采样，不是受控冷盘或压力环境。20 个样本的 p95 仍较粗，缓存、后台负载和温度可能影响结果。没有测量进程峰值内存、主状态锁等待、文件检查独立耗时或端到端 IPC 延迟。临时路径的长度会影响 JSON payload，跨机器复现时须同时比较数据形状和路径长度。
