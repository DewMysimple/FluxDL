# 0.2.1 A/B 性能复测

2026-11-09 Windows11 x64、Rust1.97 MSVC、Node24.16、WebView2。真实yt-dlp2026.07.04、FFmpeg8.0.1，原创20秒MP4，通过loopback HTTP提供；视频1080预设、相同媒体字节和配对URL、独立任务输出名、无配置代理。没有外部网站样本。

A/B为同一debug程序的安全策略切换：A仍完整元数据重提取，B使用Rust持有的刚解析可信预览，仍执行URL/模式/格式/目录/参数和配置代次校验。B,A,A,B交替，各20次，共40次；成功40、失败0、超时0，每个已完成文件实际存在且非空。B命中20/20，完整重复入队提取0次；A完整提取20次。另有故障/回退场景，均与这40次样本分开。

## 冷热、边界与复现

逐样本数组保留顺序和首个样本：进程每次全新，OS/yt-dlp缓存未主动清除，不称为OS冷启动。B每次在首次完整解析后使用热可信引用；缺失/过期/配置变化/重启是独立功能回退样本，不能混入B命中分布。对照A为显式full_recheck，不伪装成随机cache miss。可复算每组首个样本及其余19条；首次样本不足以估计冷启动p95。

同配方fixture也按策略各20次/每种writer模式，保留两组共80次逐样本；元数据固定60ms、首进度前总100ms。原始事件/URL/关联ID不提交，只公开[样本数字与固定枚举](0.2.1-latency-samples.json)。受控场景中缓存确实免掉一次入队probe；没有证据宣称消除了用户外网样本的32.95秒，也没有修改TLS、认证、代理、限流或重试安全策略。
