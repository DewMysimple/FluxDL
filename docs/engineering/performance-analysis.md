## 证据与优化决策

已确认较长部分在engine::probe（初次/二次）及实际spawn后等待有效进度。原生spawn、队列认领和SQLite通常为毫秒级。loopback仍有引擎等待，说明它并非全部是外网延迟；当前跨度无法继续拆分yt-dlp初始化、内部HTTP、探测/读取，不把这些等待归因于Rust IPC。串行有前序任务时的自然等待在单独异常/排队场景确认，不能与空队列基线混成一个p95。

本轮没有删除二次解析、信任前端格式、强制缓存或声称速度提升。二次复核确实有可见耗时，但跨站失效、权限及上下文绑定还没有足够收益/正确性证据；可信短期元数据复用可作为下一次独立实验。先保留完整安全校验和真实日志，满足任务书“不必强行实现缓存”的条件。

本轮修复了测量中发现的日志/数据库并发创建父目录竞态；同样配方复跑后writer健康。该修复是可靠性修正，没有把它包装成下载加速。后续可比较同一媒体/同一引擎/同一网络/同一缓存条件的多个交替轮次；互联网联调未测量，不能沿用本机数字宣称远程站点速度。

复现及安全边界：`npm run test:diagnostics`包含失败、复核失败、无进度、后处理、取消、重试独立attempt、串行排队、spawn失败和日志不可写仍正常下载；`node scripts/diagnostics-smoke.mjs <yt-dlp.exe>`生成真实本机证据。所有原始输出位于ignored artifacts/diagnostics与dev-logs。

## 已验证的诊断查询优化

30,000条明确标注的合成事件用于日志查询压力；分析窗口20,000条，返回100条/约54KiB。未缓存三次实际读取626.132 / 640.240 / 643.814ms，见[before](diagnostics-query-before.json)。引入有界、文件变更/generation失效及5秒TTL缓存后，同配方一次冷读288.855ms，随后两次命中7.921 / 7.896ms，见[after](diagnostics-query-after.json)。冷读差异还受OS缓存/后台负载影响，不推导因果加速倍率；命中避免重复解析且只克隆当前页。此变化仅加速诊断查询，不影响媒体校验、缓存媒体或改变队列。

命中仍验证目录/链接边界与文件签名；新内存事件立即失效，过期/文件追加失效，8并发读取合并。导出强制重新解码文件，故障/隐私测试保持通过；缓存锁被持有时事件生产者仍能完成。实时事件环2000条与受限历史缓存是不同界限，不能承诺保存无限历史。少于20条的阶段在界面和自动报告均明确“样本不足”。
