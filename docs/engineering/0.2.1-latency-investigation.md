## 已证明的成本与优化

旧入队路径在预览后再次调用engine::probe，启动独立yt-dlp提取元数据。下载子进程随后仍使用原来源URL自行提取媒体，这是正常的实际下载流程。可信预览只免去中间一次重复提取，未使用原始info JSON或签名CDN地址驱动下载。

同一debug、同引擎/原创HTTP媒体的A/B各20次，完整复核与可信命中交替。最新批次入队响应p50 1235.300→6.200ms，入队到首次有效进度2104.084→862.026ms；spawn到首次进度853.122→851.348ms，没有足够证据认定其改善。首次解析也没有改善证据。两组均20成功/0失败；二次入队提取20→0次，直接证明消除的工作。数字、p95/max、原始逐样本及边界见[后测](0.2.1-performance-after.md)。

用户一次外网样本的7.82秒复核/32.95秒等待，既不同引擎版本，也没有足够样本和代码revision，不能将本机1.2秒节省或59%端到端差值套用到该网站。

## 新的真实可观察节点

| 阶段 | 单调边界与含义 |
| --- | --- |
| download_engine_spawn | 仍是原spawn调用至取得句柄，含义不变 |
| download_first_output | spawn成功至stdout/stderr任一reader首次读取到非空字节，仅保存管线枚举 |
| download_before_dl | spawn成功至完整固定标记被当前attempt接纳；采用reader记录的Instant计算 |
| download_before_dl_to_progress | 标记读取时点至协议进度通过Manager准入 |
| download_first_progress | 原spawn成功至首个有效协议进度，含义不变，非首字节 |
| download_process_exit | spawn成功至真实退出且所有reader处理结束，终态业务落盘仍由download_terminal单列 |

before_dl使用每次进程随机命名空间、stdout精确匹配、非截断行、stream序号和attempt准入。先独立验证本机flag：纯常量模板被当缺失字段，实际未出现标记；增加%%转义后真实MP4、进度、after_move与退出0均正常。发现引擎时离线读取--help，只有明确广告before_dl、--print、--no-simulate与--progress才加新标记；未知能力继续原参数，未观测记为unobserved/无耗时。

参考[yt-dlp官方参数说明](https://github.com/yt-dlp/yt-dlp#verbosity-and-simulation-options)：print隐含quiet，现有--progress和--no-simulate继续显式保留。文档不是替代本机实验的证据。没有开启verbose、print-traffic、dump-pages或write-pages。

first output可能只是警告，before_dl也不代表媒体字节到达。现有节点无法精确分解DNS/TLS、yt-dlp初始化、站点HTTP或内部解码；仍明确未知。事件UTC/会话elapsed是记录时点；before_dl耗时优先使用真实reader Instant，不从UTC跨时钟推导。

## 可信预览与安全准入

engine/trusted_preview.rs由Rust所有，180秒Instant TTL、最多128条、单条序列化数据≤256KiB（另有对象开销）；存最小业务MediaInfo，不存完整yt-dlp JSON、请求header/cookie或提取媒体CDN地址。显示用缩略图仍是原业务DTO；私有记录只在短期内存，不导出。过期项在访问/新存入时清理，容量满按旧记录淘汰。

引用为pv_前缀加随机UUIDv4材料，与诊断规范UUID格式分离；前端无法自行创建可信内容。匹配后端规范URL、解析时模式、引擎配置代次、路径/版本/文件长度/时间指纹及格式归属。伪造、过期、跨会话、源/模式/格式/配置不匹配均走完整提取或原有安全错误。Opaque引用不是任意文件/命令权限。

命中后仍检查URL、模式/质量、真实格式能力、目录/可写性、后端参数数组。配置在准入期间变化会拒绝旧授权并提示重新解析。相同有效预览与相同选择的并发入队通过专属gate与已接受任务ID复用，避免重复创建；不同选择与无引用的旧调用仍遵循原业务校验。引用在任务构造前移除，不写SQLite。重试、取消、attempt拒旧、关键终态durable ack以及文件存在核验未简化。

preview_cache_decision仅保存固定CacheOutcome；enqueue_trusted_validate测实际本地校验；真正回退时才开始enqueue_metadata_recheck。Overview/自动报告提供命中、缺失、过期、失效、开发对照、重复复用及实际完整提取次数，按会话/环境/策略分别算耗时，不把缓存未执行的提取写0ms。

## UI、版本和历史

准备文案来自真实阶段；Rust返回的会话单调已等待时长加前端本地续计，不使用UTC估计，不跨JS/Rust原点相减。30秒阈值只作轻提示，业务下载/后处理/终态优先清除准备提示。Workspace行/详情与Quick反馈复用同一组件和短时请求合并，避免重复轮询；无记录/读失败安静降级。

任务详情「性能诊断」自动选当前会话的尝试Trace；任务ID查询也包含同Trace中任务创建前的验证阶段。保留关联预览/上次尝试入口、分页/保留截断说明；旧会话未闭合不显示为当前仍在运行。两处可复制仅含匿名ID、阶段、耗时、状态、关联Trace、已知revision与分析边界的摘要。

build.rs只在编译时获取Git SHA/dirty；部署程序不运行Git、不读源码、不联网。SessionEnvironment记录一次已净化的构建和引擎环境，事件携environment_id；环境变化产生新ID，Trace保持对应上下文。旧schema1缺失可选字段仍可读，旧版本/未知阶段跳过并计数；历史环境未知就保持unknown，禁止用最新探测值回填。统计按session/environment/cache outcome分组，未跨组平均。
