## 数据流、锁、异步和错误边界

| 链路 | 当前实现与事实源 | 锁/异步/保存/错误 |
| --- | --- | --- |
| Quick URL → 元数据 | CaptureInput → api.probe → lib.probe_media → Manager.probe → engine.probe → JSON MediaInfo | Manager短锁克隆settings/diagnostics后释放；外部进程异步，stdout/stderr并读、超时/限额；错误String经统一notify展示；解析不创建任务 |
| 入队 → 下载 → 进度 | enqueue重新probe校验 → 内存Vec push → FIFO worker claim → run_process → 标记解析 → snapshot广播 | Inner Mutex保护任务；claim安装cancel control；Inner.save在锁内同步；reader经过有界channel，tick约4Hz发全量，约2秒全量save |
| 取消/重试 | Manager.cancel修改Queued→Cancelled或运行→Cancelling；control唤醒Job终止；retry复用metadata、清进度并移队尾 | 内存状态锁内save；取消保存失败只warn；重试保存失败回退内存；run_process旧回调仅依赖active判断，缺集中转换规则 |
| 完成/失败 → 历史 | 退出码+最终媒体路径验证 → worker终态 → save → emit；历史仅Completed | 终态save失败只警告仍广播；最终文件验证在状态锁内做同步FS；移除历史只删记录，不删媒体 |
| 两窗口同步 | 单个Rust Manager；app-state-updated完整AppSnapshot；每个WebView独立Zustand展示副本 | App先refresh后异步listen，有初始竞态；无session/revision/gap检测，旧snapshot可覆盖新；focus再refresh |
| 启动/恢复 | spawn_blocking Persistence.open → settings/tasks → engines检测 → Manager → worker → WebView取snapshot | schema1 JSON文档；所有active含Queued转Interrupted；加载后即整库save；任一任务JSON错误被视为损坏，可能触发备份重建 |

## 已确认技术债与优先级

- **P0 数据兼容**：`persistence::load` 无条件设置user_version=1；未知枚举/单条JSON错误会被混同物理损坏；启动整表重写会丢掉serde未知字段。需旧库夹具、版本门禁、事务迁移和原始字段保留，不能靠空库恢复宣称成功。
- **P1 持久化一致性/锁**：全表DELETE重写，连接在Inner；同步DB占任务锁，取消/终态保存失败未确认；需要独立所有者、版本化增量写入、关键ack、进度合并和退出drain。
- **P1 同步竞态**：无版本事件、先请求后监听、任何snapshot直接覆盖；需监听先行、缓冲/合并、session与sequence、gap恢复和终态保护。
- **P1 高频成本**：每次广播clone/serialize全部任务并检查所有finalPath；App及页面订完整store，历史重复filter/sort，settings effect反复装卸主题监听。需按ID订阅/结构共享、增量progress、小范围FS刷新。
- **P2 职责/诊断**：App/CSS/Manager/Engine集中；read_lines吞I/O错误、emit忽略失败；缺集中状态机和稳定错误类别。渐进提取职责，保持参数数组、Job、权限和视觉。
- **P2 工程检查**：7项前端、18项默认Rust+1ignored fixture；缺store/reducer/迁移/回滚/写入版本测试；无lint/format脚本，无性能数据。严格Clippy基线在engine.rs:162已有needless_return失败，属重构前问题。
