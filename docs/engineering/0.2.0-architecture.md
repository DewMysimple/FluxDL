# FluxDL 0.2.0 工程架构

本页描述本轮已实现的工程边界；实际构建、回归和未测项以[验证报告](0.2.0-validation-report.md)为准。[审计](0.2.0-audit.md)保留重构前事实，不用新结构反写历史。产品仍是单媒体、单下载worker、Windows-first的外部引擎客户端，未新增产品功能或改变Midnight Glass。

## 相比0.1的改变

| 范围 | 原实现 | 本轮实现 |
| --- | --- | --- |
| 页面 | App集中窗口、页面、抽屉、订阅 | 薄App入口，窗口/页面/features/components/hooks分工 |
| 状态 | 完整snapshot反复替换，历史行重渲染 | 单一normalized cache，按ID订阅，memo selector、对象结构共享 |
| CSS | 集中样式及层叠覆盖 | 按原顺序分文件、等值Token，保留原DOM/class和层叠 |
| SQLite | 单条变化删除/重写全表，连接随Inner锁 | 独立连接owner/有界队列，按记录事务、版本与tombstone |
| 关键状态 | 运行状态与保存耦合 | owned候选→durable ack→内存提交与语义事件 |
| IPC | 全量snapshot高频广播 | typed小包+session/revision+checkpoint，snapshot按需恢复 |
| 文件状态 | 频繁快照逐项stat | 普通progress不查文件；完整恢复/详情显式刷新并验证令牌 |
| 工程验证 | 少量保护与真实smoke | 类型/lint/格式/边界测试、数据库集成、同配方基准与隔离原生回归 |

## 前端

`src/App.tsx`只选择Workspace或Quick Capture入口；`windows/`管理窗口组合，`pages/`管理Home、Queue、History和Settings，`features/capture/`管理输入/媒体选项，`features/downloads/`管理任务行和详情，`components/`管理通用反馈、弹窗和控件。`hooks/useAppSync.ts`管理生命周期，页面不自行注册领域事件。

`stores/app.ts`提供可独立创建的store及产品单例。`cache.ts`只应用已认可的领域变化：`tasksById`为null原型字典，支持旧数据中的特殊字符串ID；`taskIds`保留后端顺序；`listingRevision`仅在筛选/排序有关字段改变时推进。`selectors.ts`缓存派生任务ID。任务行按ID读取自身对象，进度不重建无关任务，主题只订阅所需标量。不可从任务派生的领域副本不会额外存入页面。

`protocol.ts`校验未知事件，`sync.ts`维护可信session/revision、有限缓冲、恢复水位与请求生命周期。先完成监听注册，再取snapshot；到达事件先缓冲，快照覆盖其revision以前的状态，随后按连续序号drain。重复/过期丢弃，缺口只合并成一个恢复请求；旧响应不能回退、未知session不能靠单条事件切换权威。失败保留最后可信cache并报告错误，I/O重试有界且可清理，不能用延时推断顺序。

单任务详情只有同session且等于当前全局revision时才合并；更高revision提示恢复，不能靠详情跳过其他领域变化。未知事件、缓冲溢出和旧请求返回都不能清掉尚未满足的恢复水位。完整协议及日志边界见[IPC合同](../IPC-contract.md)。

`styles/app.css`按原序导入tokens、themes、globals、window、workspace、downloads、details、settings、overlays、quick-capture、refinements、responsive。只抽取已有等值变量；12个固定浏览器案例与旧CSS像素一致，原生DPI范围另列验证限制。

## Rust与进程

`Manager`仍是唯一运行时任务源，管理ID/顺序、串行调度、取消/重试、候选提交，并协调Engine、Process、Persistence和Events。SQL不在Manager内执行，事件JSON不由Manager手拼；`events.rs`使用typed envelope与小型有序outbox。`lib.rs`只保留装配和退出协调，21个命令实现在`commands.rs`；`windows.rs`处理窗口/托盘和受控文件打开。

`engine/{arguments,discovery,metadata,progress,download}.rs`分离参数、探测、元数据、标记解析和下载适配器；`engine/mod.rs`保留必要出口。适配器将每路带序号的原始行转换为typed Progress/安全Log/Diagnostic，Manager不解析stdout/stderr。`process/{capture,lines,download}.rs`拥有child、reader handles、取消与回收，Windows Job实现只保留`process_job.rs`一份。`manager/files.rs`承接目录/输出校验和可选目录打开，阻塞校验在spawn_blocking执行。`transitions.rs`集中claim、cancel、retry、settle、startup recover以及attempt/阶段/流护栏。

核心约束是先验证当前attempt和合法状态，再修改字段和分配持久化版本。IPC revision、数据库mutation sequence、运行attempt分别解决不同问题，不互相替代。重试保留task ID并移到队尾，建立新attempt；旧进程的行、退出或清理不能获得新版本。真实音视频流可重置当前流百分比，不能以max百分比伪造整体进度。

进程层负责child、Windows Job、stdout/stderr reader、退出、取消与回收；引擎层负责参数数组、元数据、进度协议和依赖诊断。参数不经shell执行。Windows Job是树清理的实际保障，非Windows不声称同等验收。用户取消必须先发信号，不等待磁盘；成功退出还要验证最终媒体文件，才能提出Completed候选。

取消信号按当前状态检查，不能被满下游转发提前消费。停止失败不交还未回收child：owner保留资源、可靠交付一个pending typed诊断并合并重复原因、每轮有界重试；真实wait确认后才结束。Manager持续持active，禁止下一claim。系统长期拒绝清理时，下载owner可继续隔离等待；shutdown总12秒仍会明确失败并恢复窗口，后续可重试，不能谎称已经停止。背压不阻塞kill，也不能吞掉唯一故障。settle失败必须重试真实候选建立/确认，不能将没有pending误作终态成功；旧attempt清理只可释放匹配的Control。

`errors.rs`在Engine/Process/Writer/Window等源操作构造稳定code/phase，保留安全上下文及真实退出码；command可选`errorFormat:"structured"`返回v1 DTO，省略仍String，成功不变。`diagnostics.rs`统一URL/代理凭据、Header、Cookie、认证字段、ANSI和长度处理；每路stateful redactor保留折行状态，超长行省略后仍隐藏敏感续行。旧库日志/error/warnings只过滤内存展示副本，未改行的原始文档不主动重写。前端只将DTO.message用于Toast，保留旧String/Error兼容。

## 持久化与锁

`persistence.rs`为兼容门面，`persistence/repository.rs`拥有schema/SQL/raw字段合并，`persistence/writer.rs`拥有唯一SQLite连接线程与容量64的请求队列。任务/设置独立upsert，用户删除只删除对应记录，批次事务保证原子性。`persistence_versions`记录每项revision与删除tombstone，迟到旧写入和progress不能覆盖终态/已删除记录。

Inner短锁只捕获候选、版本、文件令牌或事件；释放后才等待writer或文件I/O。关键操作由独立owned future完成，即使IPC等待者撤销，已接受COMMIT仍会收敛。创建、认领、取消、重试、终态、删除与设置必须ack后再公开。高频progress独立约2秒节流保存，不阻塞管道消费。

明确区分数据库拒绝和ack不确定。COMMIT后丢ack先只读核对已知revision/文档，能证明提交才发布；无法核实时保留候选和诊断、阻止伪成功。关闭的12秒总deadline涵盖停止、确认和flush；超时不丢掉已提交写入，失败后恢复准入和唯一worker，不启动双份队列。

v0/v1在事务内升级v2，保留原settings/tasks文档和未知顶层/嵌套字段。无法理解的状态/行原样保留并诊断；未来schema或不兼容schema拒绝，不清库。仅SQLite物理损坏允许先字节备份再重建。启动将可理解的active任务标Interrupted，不自动恢复。详见[持久化合同](../persistence.md)。

文件刷新在锁外执行，提交时同时验证task版本、finalPath和本次刷新token；晚stat不复活已移动文件。普通progress使用缓存，详情只查一项，显式snapshot允许全部刷新；打开文件仍重新验证当前真实路径与安全目录。

## 事件与恢复

`app-state-changed`携带`{sessionId,revision,change}`，包括taskUpsert、taskProgress、taskRemoved、settingsUpdated、diagnosticsUpdated、fileAvailabilityUpdated及checkpoint。语义事件在ack后同一状态锁捕获确切task+index；快速终态→retry不能只发最后状态。普通runtime/log合并约250ms发布，不克隆全部历史。publisher在锁外按顺序emit，失败留诊断，不复用序号。

snapshot/详情在最终短锁内先flush全部pending progress/log，再克隆状态与revision，避免快照已含日志随后append重复；完整upsert清pending日志。日志最多100行/每行1600字符，重复文本可真实出现，不做内容去重。每6秒无数据checkpoint推进revision，暴露丢失的唯一终态，即使之后没有业务事件也能恢复。

## 验证与运行

本地使用`npm run desktop:dev`，浏览器仅预览。前端检查为typecheck、lint、format:check、test、build；Rust为format:rust、lint:rust、test:rust，真实worker另执行`scripts/test-queue.ps1`。`test:styles`复现12项旧CSS等值。性能命令及采样说明见[before](0.2.0-performance-baseline.md)与[after](0.2.0-performance-after.md)，禁止覆盖before原始证据。

`desktop-smoke.mjs`使用本地原创HTTP素材、真实yt-dlp与隔离debug数据/profile；可选旧库seed和音频回归。`native-desktop-smoke.mjs`补充真实目录Cancel、注册托盘菜单链和活引擎停机，未测项与物理点击边界单列。测试只管理自己创建的进程，release没有测试端口/目录覆盖入口。NSIS沿用原构建策略，不附带引擎、不自动下载引擎、不扩大capability。

本轮不commit/push、不创建Release，不覆盖用户正在运行的发行版。最终版本、构建产物、命令结果与未覆盖项统一见验证报告，历史0.1报告保留当时含义。
