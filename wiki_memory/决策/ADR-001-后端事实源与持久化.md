# ADR-001 后端事实源与持久化

## 背景与授权

用户的 MVP 要求真实双窗口、下载队列和重启持久化，技术栈指定 Rust/Tauri。具体状态管理与数据库结构由 Agent 在该实现授权内选择；没有将这些细节记为用户逐项批准。

## 选择及实施状态

已实现：`Arc<Manager>` 为任务、设置、引擎诊断的唯一事实源；一个 FIFO worker 串行执行，两个 React 窗口通过完整快照展示。SQLite schema 1 保存设置及任务 JSON，状态变化保存，进度约两秒保存；重启残留 active（含 queued）统一转 Interrupted，由用户重试。

## 理由与代价

本地单用户 MVP 用同一状态机避免窗口分歧，事务保存和显式中断避免假恢复。数据库损坏先保留备份，历史删除只删记录。

当前同步事务在异步运行时线程内持锁执行，重写全部任务；大量记录会扩大快照与保存成本，未做规模基准。此决策不等于已实现数据库 actor、增量写入、分页或正式跨版本迁移框架。扩大规模前按 `docs/persistence.md` 测量和调整。

## 验证线索与适用范围

2026-11-09 核对 `manager.rs`、`persistence.rs`、Zustand 与正式文档。历史 worker fixture 和真实桌面报告覆盖串行、取消/重试、重启与中断，见 `docs/validation.md`；本轮仅核对，不复跑。适用于当前 0.1.0 本地串行架构，不能推导非 Windows 进程保证。
