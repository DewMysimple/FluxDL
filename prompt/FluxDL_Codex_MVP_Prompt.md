## 1. 产品愿景与边界

### 1.1 产品定义

**FluxDL** 是一个专为 Windows 设计的、本地优先的、高品质 yt-dlp GUI 客户端。

它必须同时满足三个目标：

- **A. 个人自用**：启动轻快、无账号、无服务器、快捷粘贴、尽可能少配置；
- **B. 可开源发布**：目录清楚、可维护、有测试、说明文档与可构建的 Windows 安装包；
- **C. 精品桌面体验**：Raycast 式视觉精致度、舒适的信息密度、可靠的系统交互、克制有意义的动效。

设计哲学：**第一眼精致，第二眼清晰，长期使用舒适。**

### 1.2 MVP 明确包含

1. **真正的双窗口**：Quick Capture 快速浮窗 + Workspace 主工作台；
2. **真实 yt-dlp 引擎检测与调用**：自动检测 PATH、允许手动选择 `yt-dlp.exe`，支持用户路径优先与可选内置引擎；
3. **视频链接解析**：读取标题、来源、时长、缩略图、可用格式等数据，并清晰处理失败；
4. **两种主要下载方式**：视频（最佳可用、合理 MP4 偏好）和仅音频（可用时转为 MP3，明确依赖 FFmpeg）；
5. **真实下载队列**：添加任务、默认串行执行、实时进度、速度、ETA、取消、失败重试、打开文件/目录；
6. **本地持久化**：任务和历史记录在关闭再打开后仍可查看；异常退出后在途任务标为“已中断”，可以重试；
7. **设置**：下载目录、下载格式默认值、引擎路径、FFmpeg 路径、暗/亮主题、任务列表密度；
8. **Windows 托盘与关闭行为**：保证用户理解后台下载与真正退出的区别；
9. **可打包**：Tauri 2 Windows NSIS `setup.exe` 构建配置与实际构建步骤；若环境具备则产出文件；
10. **必要测试、使用说明、故障诊断**。

### 1.3 明确不属于此版 MVP（可留扩展点，不要求实现）

- 账号系统、云同步、远程下载、P2P；
- DRM 绕过、付费内容限制绕过、破解访问控制；
- 浏览器扩展、完整媒体播放器、封面编辑器；
- 完整播放列表批量下载、多用户队列与下载规则引擎；
- 任意用户自定义 yt-dlp CLI 参数输入框、复杂代理/Cookies UI；
- 自动下载第三方二进制文件并静默替换；
- 复杂暂停/继续按钮：**只有在真正验证进程生命周期与恢复语义后才能展示“暂停”**，MVP 先提供“取消”和“重试”；
- 单一 `.exe` 便携式全依赖封装承诺：NSIS 安装包优先，便携构建可作为后续独立目标。

不要因为某个功能尚不在 MVP 范围内，就用不可工作的按钮假装它已经实现。

## 2. 视觉身份：Midnight Glass

### 2.1 核心风格

界面基于 **Raycast 式轻奢精致感**，但必须面向 Windows，不复制 macOS 红黄绿窗口按钮。

关键词：

- 深石墨、哑光陶瓷、柔和磨砂、低饱和银紫；
- 轻盈、安静、专业、细节丰富但不炫技；
- 细边框、柔和大范围阴影、清晰的文字层级；
- 一眼能辨认的重要操作，避免“网页 Dashboard 味”；
- 主界面不透明为主，**毛玻璃只用于 Quick Capture、浮层/菜单及少量过渡**。

不允许：大面积炫彩渐变、荧光描边、持续流光、浮夸 3D、透明到难以阅读的页面、全局夸张弹簧动画、巨型无意义 KPI 卡片。

### 2.2 基础颜色（可根据可读性微调）

建议定义语义化 CSS 变量，而不是在组件内到处硬编码：

| Token | 暗色建议值 | 用途 |
|---|---|---|
| `background` | `#121319` | 页面底层 |
| `sidebar` | `#191A21` | 左侧导航 |
| `surface` | `#20212A` | 表单、卡片 |
| `surface-elevated` | `#2B2936` | 浮层、选中态 |
| `border` | `#383744` | 1px 低对比边框 |
| `accent` | `#B4A5F1` | 核心操作、进度 |
| `accent-hover` | `#C5B9F7` | 主要按钮悬停 |
| `text-primary` | `#F0EDF6` | 标题、正文 |
| `text-secondary` | `#A09BAB` | 次级说明 |
| `success` | `#8DC8AE` | 完成 |
| `warning` | `#E5BB82` | 提醒 |
| `danger` | `#E995A2` | 错误 |

浅色主题设计为暖白/银灰/淡紫的柔和变体，**不要简单对暗色值取反**；保证 WCAG 合理对比度，所有文本实际可读。

### 2.3 字体、图标、圆角、尺寸

- 字体：优先 `Segoe UI Variable` / `Segoe UI`，中文回退 `Microsoft YaHei UI`、系统字体；不从互联网运行时拉字体。
- 字号：普通正文约 13–14px；小标签尽量不低于 12px；页面标题约 20–22px。
- 图标：Lucide；大小和线宽统一；重要图标采用少量原创品牌化处理。
- 圆角：主窗口/浮窗视觉外框约 16–20px，面板 12–14px，按钮/输入框 8–10px；以整体比例为准。
- 间距：采用 4/8px 基础步进体系，主内容内边距约 28–32px。
- Hover 轻微提亮，Selected 弱银紫高亮，Focus 有明显可访问的轮廓；三者不可混为一谈。
- 动效：基础 120–180ms；抽屉/展开 200–240ms；优先 opacity/transform；支持系统 `prefers-reduced-motion`。
- 下载百分比不能捏造平滑数值；进度展示可以用短暂过渡，但必须以真实引擎事件为数据源。

### 2.4 响应与空状态

- Workspace 初始约 **1120 × 740px**，最小尺寸按内容与系统限制合理设置；缩窄时导航收为图标条，详情抽屉改覆盖式。
- Quick Capture 建议宽 **600–640px**、高度自适应，出现在当前显示器上方约 20% 位置，并考虑多显示器边界。
- 空状态不能放满屏营销插画，只要品牌化小图标、简洁文案和明确下一步。
- 所有容器在 Windows 缩放 125%、150% 以及长中文文件名时不得严重溢出。

## 3. 双形态窗口：真实功能，不是两个假的页面

### 3.1 Quick Capture（快速捕获窗口）

**用途**：用户从任意桌面场景快速贴入链接、解析、选择简易下载方式、加入队列、回到工作。

界面结构：

1. 顶部品牌图标、`FluxDL`、弱化的 `Quick Capture` 字样、关闭/收起入口；
2. 一条视觉权重很高的链接输入框，带粘贴按钮；
3. 未输入时底部仅展示快捷提示和“打开工作台”；
4. 解析中出现精致的局部 loading / skeleton；
5. 解析成功后向下**展开**简洁的媒体卡：缩略图、标题、时长、来源、视频/音频选择、格式/质量预设、加入队列；
6. 加入队列后展示短暂的“已加入队列”状态，提供“查看任务”，随后可自动隐藏，但不能关闭/终止实际下载进程。

交互：

- `Ctrl+V` 粘贴；`Enter` 在输入时启动解析；`Esc` 关闭当前弹层或隐藏浮窗。
- 不要静默持续读取剪贴板；只有用户点击粘贴或明确触发快捷操作时读取。
- 不默认永远置顶；避免和其他软件争夺焦点。
- Quick Capture 被再次打开时可以复用单例窗口，不要无限创建同名窗口。
- 可以通过工作台按钮和托盘菜单打开 Quick Capture；若全局快捷键易于可靠实现，可添加并允许配置，但不作为 MVP 阻塞项。
- 页面导航方式要适配 Tauri 2 的真实多窗口加载，不能依赖单纯 `display:none` 来冒充双窗口。

### 3.2 Workspace（主工作台窗口）

**用途**：查看当前任务、管理队列与历史、调整下载偏好、查看引擎状态。

整体布局：

- 顶部约 44–48px 融合式标题栏；保留正确的 Windows 最小化/最大化/关闭行为与可拖动区域。
- 左侧约 192px 的稳固导航，项目：**工作台、下载队列、下载历史、设置**；底部显示简洁的引擎状态。
- 右侧主内容不做过多固定卡片，信息密度随页面调整。
- 解析结果、任务详情使用**右侧抽屉**（建议宽 380–420px），在小窗口改为覆盖浮层。
- 两个窗口共享 Rust 后端同一任务源，避免状态不同步。

## 4. MVP 页面与构图细则

### 4.1 工作台首页

从上到下：

1. 简洁页标题 `下载工作台` 和一句轻量副标题；
2. **视觉主角：链接输入面板**，包含 URL、可见的解析按钮、当前默认预设提示，面板高度控制在约 120–136px 内；
3. `正在下载` / `当前任务` 区域：只展示少量活跃任务，用户可进入任务中心；
4. `最近完成` 区域：展示少量历史记录；
5. 空状态：如还没有下载记录，以清楚的引导替代统计数字。

首页绝不堆砌“累计下载次数”“今日流量”之类的伪 KPI。

解析成功后：

- Workspace 打开右侧媒体详情抽屉；
- 抽屉含缩略图、视频信息、视频/仅音频切换、真实可用格式选择、保存目录摘要、加入队列主按钮；
- 首屏显示最常用选项；高级格式细节可放折叠区；
- 若为播放列表，**必须显式提示“当前 MVP 不执行整列表批量下载”**，不能误把整列表无提示地加入队列。可在明确单条信息时支持下载该视频，否则友好阻止。

### 4.2 下载队列

采用 **紧凑而精致的横向任务行**，不是大型视频卡片墙。

建议舒适密度单行约 76–88px；紧凑密度约 60–68px。每条任务：

- 可用的 16:9 缩略图 / 媒体占位图；
- 标题与安全截断、省略号和完整标题 Tooltip；
- 清晰的格式/分辨率/来源辅助信息；
- 状态标签，必要时展示进度条、速度和 ETA；
- 悬停与键盘聚焦时出现操作按钮（取消、重试、打开目录、详情），**预留按钮空间避免文字跳动**；
- 点击任务打开右侧详情抽屉，展示下载信息、路径、错误、精简日志（有数量上限）；
- 显示 `进行中 / 等待中 / 全部` 筛选；总状态来自后端而非前端假计时器。

状态展示要求：

- Queued：等待中，不显示虚假的进度；
- Resolving：正在解析；
- Downloading：真实进度、速度、ETA；若没有总字节数则展示不确定进度与已下载字节数；
- PostProcessing：正在合并/处理文件，不能继续假装下载百分比在增长；
- Completed：绿色完成状态 + 文件操作，不展示多余的 100% 动画；
- Failed：可读错误摘要 + 重试；
- Cancelling / Cancelled：区分取消中与已取消；
- Interrupted：上次未完成，可重试，不能自动声称已恢复。

### 4.3 下载历史

- 按时间倒序显示，支持标题/来源的本地搜索；
- 展示标题、文件类型、完成时间、输出位置；
- 支持打开文件、打开文件所在目录、复制来源链接、仅删除历史记录；
- 如果文件已被用户移动或删除，显示“本地文件不存在”，不能假装“文件可用”；
- 默认不提供“一键删除本地文件”，避免误删。

### 4.4 设置

分组清晰，不要把全部设置塞进密密麻麻的表单：

**常规**：默认保存目录、完成后行为、列表密度。  
**下载**：视频质量预设、默认视频/音频模式、并发数（MVP 默认 1；可仅展示为当前固定值）。  
**外观**：暗色/浅色/跟随系统，减少动画偏好。  
**引擎**：yt-dlp 路径及版本、FFmpeg/FFprobe 检测与路径、依赖诊断。  
**关于**：版本、项目主页（若存在）、开源许可证、诊断信息入口。

设置更改需即时或明确保存，重启后保留；路径选择必须使用原生文件/目录选择器。

## 5. 真实下载链路与用户流程

必须实现以下端到端流程：

1. 启动应用 → 检查当前设置及引擎状态。
2. 用户输入合法 URL（http/https）→ 点击解析。
3. Rust 后端启动本地 `yt-dlp` 解析，返回真实 JSON 元数据。
4. UI 展示真实视频标题、缩略图、时长、来源和格式选项；处理元数据缺失。
5. 用户选择视频/音频、格式/质量和目录 → 加入队列。
6. Rust 创建持久化任务，并由独立队列执行器启动真实下载进程。
7. Rust 解析进度并更新持久化数据，通过 Tauri 事件/Channel 推送状态至所有窗口。
8. 下载完成后，确认退出码、后处理状态及最终文件路径，标记 Completed，历史可打开真实文件。
9. 下载失败时保留必要日志并显示友好错误，支持重试。
10. 用户取消时真正停止相应下载子进程及需要清理的子进程，不只是从 React 里移除任务。
11. 正在下载时关闭/重新打开窗口，任务不因为前端窗口销毁而丢失（应用进程仍运行时）。
12. 整个应用异常退出并重新打开时，在途任务标记 Interrupted；用户主动重试，不能默认自动继续。

**下载进度和生命周期状态的权威来源只能是 Rust 队列管理器。** React/Zustand 是展示层缓存，不是后端事实源。

## 6. 下载引擎与依赖管理

### 6.1 引擎模式

设计一个可扩展的 `EngineResolver` / `DownloadEngine` 抽象，统一暴露解析、下载启动、取消、检测能力。至少兼容：

- **Custom/Local**：用户在设置中选择现有 `yt-dlp.exe` 的完整路径；
- **PATH**：自动发现系统 PATH 中的 `yt-dlp`；
- **Bundled/Sidecar**：如项目准备了允许分发的 `yt-dlp` 二进制，可在 Windows 发布包内携带；

推荐解析顺序：用户指定的有效路径 → 随应用内置的有效引擎 → PATH，具体决定记录于文档；UI 能明确显示当前正在使用的来源和版本。

Tauri 2 可使用官方 Sidecar `bundle.externalBin`，或者经过官方文档验证、可稳定定位安装资源的 Rust 进程运行方式。**不要混淆 Tauri 1 的示例、JS 直接调用 Sidecar 与 Rust 后端调用方式。** 实现上优先让 Rust 控制下载子进程，前端只通过受控 command API 操作。

### 6.2 FFmpeg / FFprobe

- 自动检测；允许用户手动设置路径或所在目录；
- 优先确保视频音轨合并可用；仅音频转 MP3 依赖 FFmpeg；
- 如果缺少 FFmpeg，不要让用户下载后才发现失败：在需要合并/转码时提前明确提示；对于不需后处理、确实可用的直接格式可以提供安全降级；
- 不要把 Python 的同名 `ffmpeg` 包误当做 FFmpeg 可执行程序。

### 6.3 YouTube 相关 EJS / JavaScript Runtime

新版 yt-dlp 对完整 YouTube 支持可能还需要 `yt-dlp-ejs` 和支持的 JS 运行时（例如 Deno）。

MVP 必须：

- 在引擎诊断页解释并检测**可观察到**的依赖状态或运行告警；
- 不要声称单凭 `yt-dlp --version` 就能验证所有站点支持；
- 若解析因 JS runtime / EJS 缺失失败，显示清楚的错误帮助和官方指引；
- 不默认偷偷从第三方地址下载可执行文件；将自动安装/更新留到后续版本。

### 6.4 参数安全与命令处理

- **绝不拼接 shell 字符串执行 URL 或路径**；统一以可执行文件 + 参数数组启动进程。
- 严格处理 URL、输出路径和格式参数，不能把用户链接当额外 CLI 选项。
- 考虑使用 `--ignore-config` 来保证应用行为可预测，避免用户本机 yt-dlp 配置引发不受控行为；如果保留配置继承，必须清楚标注并验证风险。
- 默认单视频模式要防止链接意外触发整个播放列表下载。
- 输出目录必须可写，使用 yt-dlp 安全文件名模板并避免文件名冲突；不要自己随意用原始标题拼接路径。
- 检查可执行文件真实存在、能运行及版本；执行超时、退出码、stdout/stderr 都要处理。
- 不允许前端任意传入可执行路径或任意 shell 命令执行；后端只接收经过类型校验的下载选项。

## 7. 进程管理与实时进度：关键工程要求

**这部分优先级和界面一样高。**

- 使用 Rust 异步机制（Tokio 等与 Tauri 2 兼容的方式）执行后台任务，UI 绝不能因同步调用而卡住。
- 读取 stdout/stderr 时避免阻塞和死锁；两路输出必须正确消费；日志有行数/内存上限。
- 可用 `yt-dlp -J` 或等价的官方元数据选项解析链接；用 `--newline` 和 `--progress-template` 输出相对稳定、可识别的下载/后处理进度记录。
- 解析要容忍空字段、未知总大小、颜色码、格式变化以及不同语言/版本；不要仅靠硬编码匹配 `[download] 42.3%`。
- 必要时分离专用进度标记与常规日志；未知进度为 indeterminate，不伪造百分比。
- 向 UI 的进度广播要节流（例如约 4–10 次/秒），防止大量 React 重渲染。
- 下载任务必须有唯一 ID、可追踪 PID/子进程句柄、可取消操作和可靠状态迁移。
- **取消必须终止真实执行进程**；注意 Windows 中 yt-dlp 可能衍生 FFmpeg，尽可能妥善处理子进程树，避免孤儿进程。若只能提供有限保证，应明确记录。
- 对同一任务的并发“取消/完成/失败”进行竞争条件保护，确保终态只写入一次。
- 实际文件路径应从 yt-dlp 下载/后处理结果可信地获取（例如使用官方输出模板的完成阶段打印），不要盲猜最终扩展名。
- 保持队列有序：默认一次一个任务，结束后自动开始下一个；支持取消排队任务与重试失败/中断任务。
- 如果下载中关闭 Workspace，下载由 Rust 后端继续执行，和 React 窗口生命周期解耦。

建议最小状态机：

`queued → resolving → downloading → postprocessing → completed`

异常分支：`failed`、`cancelling → cancelled`、`interrupted`，必要时允许略过并非每次都有的阶段。

## 8. 前后端接口、数据与持久化

### 8.1 推荐命令接口（名称可调整，但语义必须存在）

- `get_app_state`：启动时一次取得设置、引擎状态与任务摘要；
- `detect_engines`：返回 yt-dlp / FFmpeg / FFprobe 与推荐 JS runtime 的诊断；
- `probe_media(url)`：解析真实媒体元数据，不下载；
- `enqueue_download(input)`：校验配置、创建任务并入队；
- `list_tasks(filter)`：获取真实任务列表；
- `cancel_task(task_id)`：取消排队/运行中任务；
- `retry_task(task_id)`：失败/取消/中断后的合理重试；
- `list_history(query)`：返回持久化历史；
- `remove_history_record(id)`：仅删除记录，默认不删除文件；
- `get_settings` / `update_settings`：读取与更新配置；
- `open_download_file` / `reveal_in_folder`：仅针对已记录、安全且存在的路径进行系统操作；
- `show_quick_capture` / `show_workspace`：协调两个真实 Tauri 窗口。

前端统一在一处封装 Tauri IPC，不能在组件中随意散布未校验的 `invoke` 字符串。

### 8.2 事件设计

使用明确命名与类型化载荷（例如 `task-updated`、`task-log-appended`、`engine-status-updated`）。

- 多窗口都能订阅；
- React 组件挂载时订阅、卸载时取消订阅；
- 防止因为窗口重复打开而产生重复监听器；
- 初始状态/重新聚焦时应调用快照读取，**事件是增量通知而非唯一可信存储**；
- 高频进度更新如适合 Tauri 2 Channel 可使用 Channel，保持协议一致。

### 8.3 数据模型（建议）

`MediaInfo`：URL、标题、媒体 ID、来源、时长、封面、isPlaylist、formats。  
`FormatOption`：formatId、扩展名、分辨率、音视频类型、码率/大小（可空）、是否需要 FFmpeg。  
`DownloadTask`：id、URL、标题、目标格式、输出目录、状态、进度、速度、ETA、下载字节数、最终路径、错误、创建/更新时间。  
`AppSettings`：引擎模式/路径、FFmpeg 路径、下载目录、默认预设、主题、列表密度、关闭行为。  
`EngineDiagnostics`：依赖路径、版本、来源、检测结果、可读提示。

### 8.4 持久化策略

- 优先 SQLite（Rust 侧管理，内置数据库、迁移脚本，项目路径使用系统 AppData 而非安装目录）。
- 如果 SQLite 对当前环境造成实质性阻塞，可采用可靠的本地文件方案作为**明确记录的临时折中**，但不能把持久化功能直接省略。
- 保存设置、任务与历史；不要把持续变化的每个进度字节都高频写磁盘，可按状态变化和合理时间间隔持久化。
- 应用重新启动时将残留 `resolving/downloading/postprocessing/cancelling` 任务重整为 `interrupted`，保留原任务记录以便重试。
- 文件缺失、目录不可写、数据库文件不存在或损坏均应有可读错误或安全恢复策略。

## 10. Windows 本地集成、托盘、打包

### 10.1 标题栏与窗口行为

- 优先保证 Windows 上的拖动、最大化、最小化、窗口缩放和原生系统菜单行为正确；
- 标题栏可以做自定义视觉外壳，但不能牺牲原生窗口功能；
- Quick Capture 的窗口边框与圆角视觉符合 Tauri 2/Windows 实际可实现范围；阴影/透明只能在可读性和稳定性可控时添加；
- 多屏与高 DPI 下不应打开到屏幕外。

### 10.2 托盘与退出语义

MVP 提供可发现的托盘菜单：`打开工作台`、`快速捕获`、`退出 FluxDL`。

- 仅关闭 Quick Capture = 隐藏 Quick Capture，不等于退出程序；
- 正在下载时关闭 Workspace：提示“在后台继续 / 停止任务并退出 / 取消”；
- 选择后台继续后，应用仍处于系统托盘，可重新打开 Workspace；
- 选择真正退出时，安全停止/清理正在运行的子进程与资源；
- 没有活动任务时的窗口关闭行为要一致且可解释；
- 若平台限制导致后台行为不能可靠实现，不可假装任务仍在运行，必须提供明显的保守退出方案。

### 10.3 EXE 打包

主要交付：**Windows x64 NSIS 安装包**（通常名为 `*-setup.exe`），以及可运行的应用程序二进制文件。不要把“安装包 EXE”和“单文件绿色便携 EXE”混为一谈。

- 正确配置 Tauri 2 bundle、图标、应用名称、identifier、Windows NSIS；
- 使用已验证的官方引擎二进制资源，才允许将其作为 Sidecar/资源随包分发；不能假装下载依赖已经存在；
- 若用户本地只有 `yt-dlp.exe`，可以先产出**外部引擎模式可运行**的安装包，但 README 必须醒目说明如何定位和选择本地 yt-dlp、FFmpeg，以及与“开箱即用捆绑版”的差异；
- 若采用 Sidecar，确保 Tauri 2 目标架构命名、安装路径和运行权限与官方文档一致；
- 检查 FFmpeg 构建的具体许可证与再分发义务；提供真实的第三方声明，不能写假许可证；
- 不在构建或运行时悄悄下载未校验来源的第三方可执行文件。

优先在 Windows 主机上实际执行打包；如果当前环境不是 Windows，则至少完成构建配置、基础静态验证及 GitHub Actions Windows 构建工作流，并明确本机未执行 Windows 打包。

## 11. 隐私、安全、合规

- 本地优先：无登录、无遥测、无远程数据库、无广告；
- 不收集、记录或上传用户下载记录与私人链接；日志中可对 URL query/token、Cookies 等敏感字段作脱敏；

- 所有外部路径和 URL 都需要校验，优先使用系统级文件/目录对话框；
- 缩略图若来自第三方 URL，提供加载失败占位和合理的 CSP/网络策略，不要为了图片显示把权限全开；
- 依赖版本、许可证、来源必须可追溯。

## 12. 必须考虑的错误与边界场景

至少正确处理并可通过 UI 演示或测试验证：

1. URL 为空、无效或非 http/https；
2. URL 指向不支持的站点或失效内容；
3. 视频需要登录/受限，但默认不自动抓取任何凭据；
4. 视频可下载格式为空，或用户选择的格式不可用；
5. yt-dlp 不存在、路径错误、权限不足、版本命令无法运行；
6. FFmpeg/FFprobe 缺失，尤其在需要音视频合并或转 MP3 时；
7. EJS/JavaScript runtime 缺失导致兼容性问题；
8. 保存目录不存在、不可写、磁盘空间不足；
9. 网络断开、进程返回非零退出码、解析超时；
10. 未知总大小时进度显示；
11. 任务快速取消/重试的竞态；
12. 任务完成后用户移动/删除了文件；
13. 两个窗口同时打开、关闭、切换；
14. 应用重启后任务恢复显示；
15. 仅有 PATH 版本引擎、仅有手动配置引擎、内置 Sidecar 缺失的不同部署形态；
16. 小窗口、长标题、长中文路径、125–150% DPI、浅色主题。

错误信息要面向普通用户说明“发生了什么、可能为什么、下一步怎么做”，并在详情中保留可复制的技术诊断，不只展示原始终端堆栈。
